ble-console 韌體更新操作說明

DTS-CS01 · nRF54L15 + MCUboot · MCUmgr SMP over BLE

在 ble-console 的 Firmware update 分頁選好 zephyr.signed.bin，按 Update，約 30–60 秒就能透過藍牙完成更新，不需要安裝 App。新版若沒有正常運作，板子會自動退回舊版。

1概述

Firmware 分頁用 MCUmgr SMP 協定更新韌體，和手機上的 nRF Connect Device Manager 是同一套協定。2026-11-03 已在硬體上實測，從 3.4.1 升級到 3.4.2：

映像大小274 KB
上傳時間15.6 s
上傳速度17.4 KB/s
  • 同一個連線：Control 分頁（馬達命令）和 Firmware 分頁共用一個藍牙連線。板子只接受一個連線，所以不必斷線就能在兩個分頁間切換。
  • 安全機制：只有用本專案金鑰簽章的映像才能開機；新映像先以 test 模式執行，由韌體自己 confirm，出問題會自動退回舊版。

2事前準備

每次更新前確認以下四項。最容易忘的是第 2 項：版本號沒改，檔案會被判定為「與板子上的韌體相同」而拒絕上傳。

  1. 瀏覽器：電腦上的 Chrome 或 Edge（Windows、macOS、Linux、Android 皆可）。Safari、iOS、Firefox 不支援 Web Bluetooth。
  2. 改版本號：編輯專案根目錄的 VERSION，至少把 PATCHLEVEL 加 1（例如 3.4.2 → 3.4.3）。
  3. 建置韌體：在 nRF Connect SDK 環境執行 west build -b nrf54l15dk/nrf54l15/cpuapp。
  4. 找到檔案：下表兩個擇一。
檔案位置說明
zephyr.signed.binbuild/DTS-CS01_54L15xx/zephyr/簽章過的映像，建議使用
dfu_application.zipbuild/頁面會自動取出裡面的 bin
同一資料夾的 zephyr.bin 是未簽章版本，不能用來更新。ble-console 要用 http://localhost（或 https）開啟，用 file:// 開啟時 Web Bluetooth 無法使用。

3連線

連線成功後，頁面頂端會顯示「NUS RX/TX + SMP ready」。

  1. 先關掉其他連到板子的工具（手機 nRF Connect Device Manager、桌機版 nRF Connect 等）。板子同時只接受一個連線。
  2. 用 Chrome 或 Edge 開啟 ble-console，按 Connect。
  3. 在裝置清單中選 DTS-CS01_xxxxxx（xxxxxx 是板子 BLE 位址的最後 6 碼），按「配對」。
  4. 切到 Firmware update 分頁，頁面會自動讀取一次板子上的映像狀態。

若顯示「no SMP service」，表示板子上的韌體沒有 MCUboot（例如用 -DSB_CONFIG_BOOTLOADER_NONE=y 建置的版本），只能用 J-Link 透過 SWD 燒錄。

4畫面說明

Firmware 分頁由上到下分為五個區塊。下方的 Traffic log 與 Control 分頁共用，SMP 相關訊息以綠色的 SMP 標示。

區塊內容用途
Images on the boardslot 0 / slot 1 的版本、hash、狀態標籤；右上 Read state 重新讀取看板子目前的版本
Image file選檔按鈕，以及 File、Version、Size、Hash、Vs. board 五個欄位確認選對檔案、版本比板子新
UpdateUpdate、Cancel upload、Chunk 設定、六步驟清單、進度條日常更新
Switch backSwitch to slot 1 (x.y.z)切回上一版
Single stepsUpload only、Mark slot 1 for test、Confirm running image、Reset board除錯或特殊測試

slot 是什麼：slot 0 是正在執行的映像，slot 1 用來接收上傳的新映像。重開機時，MCUboot 依狀態決定是否交換兩個 slot。

狀態標籤

標籤意思
active正在執行的映像
confirmed已確認為永久版本，重開機不會退版
unconfirmed尚未確認；若在 slot 0，下次重開機會退回舊版
pending (test)已標記為測試開機，下次重開機會交換到 slot 0
permanent已標記為永久交換（本流程不使用）
not bootable映像無法開機

Vs. board 欄位

顯示意思
newer than running …較新，正常更新
identical to the running image完全相同，會被拒絕；請改 VERSION
older than running … (downgrade)降版，按 Update 時會先詢問
already uploaded to slot 1已在 slot 1，Update 會跳過上傳
same version …, different build版本號相同但內容不同；建議改 VERSION

Chunk 控制每次上傳請求的資料量。預設 auto 會依板子回報的緩衝區大小決定，通常不需要改；上傳一直逾時才改成 512 B 或 128 B。

5一鍵更新（Update）

選檔後按 Update，六個步驟會自動依序完成。全部打勾並出現綠色的「Updated to x.y.z; the firmware confirmed it.」即表示成功。

操作

  1. 確認馬達靜止（沒有在換檔、沒有 F/R 運轉）。
  2. 在 Image file 區選檔，確認 Version 是新版本、Vs. board 顯示「newer than running …」。
  3. 按 Update 並等待完成。過程中不要關閉分頁、不要讓板子斷電。

六個步驟

步驟做什麼實測時間
1. Check讀板子狀態、比對檔案；相同就停止，較舊就先詢問< 1 s
2. Upload把映像寫入 slot 1，顯示進度、速度、剩餘時間約 16 s
3. Test把 slot 1 標記為下次開機測試< 1 s
4. Reset板子重開機，MCUboot 交換 slot 0 與 slot 1幾秒
5. Reconnect自動重連，不需再選裝置；最多等 90 秒幾秒到十幾秒
6. Verify確認 slot 0 是新映像，等韌體約 5 秒後自己 confirm；最多等 30 秒約 5 s

上傳中可按 Cancel upload 中止。已上傳的部分留在 slot 1，不影響目前執行的韌體；之後用同一個檔案再按 Update，會從中斷處續傳。

6切回上一版

更新完成後，不必重新上傳就能切回上一版。MCUboot 更新時是「交換」兩個 slot、不是覆蓋，所以舊版完整保留在 slot 1；本專案的 MCUboot 也沒有啟用降版防護。

操作

  1. 按 Read state，確認 slot 1 是要切回的版本。
  2. 按 Switch back 區的 Switch to slot 1 (x.y.z)，按鈕上會顯示 slot 1 的版本。
  3. 在確認視窗確認「從哪版切到哪版」後按「確定」。
  4. 板子重開機、自動重連，約 5 秒後舊版韌體自己 confirm，出現綠色「Switched to x.y.z」即完成。

切換後兩個版本互換位置：slot 0 是舊版、slot 1 是剛才的新版，再按一次就能切回新版。

無法切回的情況結果替代方式
更新後又上傳了別的映像（含中途取消的上傳）slot 1 已被覆蓋，舊版不在了重新上傳舊版 .bin，頁面會先詢問是否降版
slot 1 是沒有 MCUboot 的舊版韌體不會自己 confirm，下次重開機又退回用 J-Link 透過 SWD 燒錄
新版改過設定資料的格式舊版可能讀不懂新版存的資料（例如零點）切回後重新教零點（Z）
slot 1 只能保留「上一版」。每次發布時請把 zephyr.signed.bin 依版本號另外存檔，需要更早的版本時才能重新上傳。

切回按鈕尚未在硬體上實測。

7單步操作

單步按鈕把 Update 拆開來做，用於除錯或特殊測試，一般更新不需要。依序按 Upload only → Mark slot 1 for test → Reset board，結果與 Update 相同。

按鈕做什麼何時使用
Upload only只上傳到 slot 1，不標記、不重開機先放好新版、之後再切換；測試馬達運轉時拒絕上傳
Mark slot 1 for test把 slot 1 標記為下次開機測試上傳完成後、準備切換時
Confirm running image把目前執行的映像手動標為永久韌體通常會自己 confirm；手動會跳過「韌體能正常運作」這道檢查
Reset board重開機並自動重連標記測試後切換；或確認更新後重開一次不會退版

Confirm running image 與 Reset board 會先跳出確認視窗，按「確定」才執行。

8錯誤訊息與排除

失敗時該步驟標示紅色 ✕，錯誤訊息顯示在進度條下方，也會記在 Traffic log。任何一步失敗，板子都會繼續執行原本的韌體。

訊息原因處理方式
not a signed MCUboot image選到 zephyr.bin 或非映像檔改選 zephyr.signed.bin
this image is already running檔案與 slot 0 完全相同改 VERSION 後重新 build
board busy: the motor is moving馬達正在換檔或 F/R 運轉，板子拒絕開始上傳或重開機到 Control 分頁按 Stop，或等換檔完成再試
slot 1 is empty還沒上傳就按了 Mark slot 1 for test 或 Switch先上傳
SMP request timed out藍牙訊號弱或連線不穩靠近板子重試；仍失敗就把 Chunk 改為 512 B
board did not come back within 90 s重開機後沒有重新廣播確認板子有電，手動按 Connect，再按 Read state
board runs x.y.z, not the expected imageMCUboot 拒絕了新映像（簽章金鑰不符）或已退版確認是用專案金鑰簽章的 build
still unconfirmed after 30 s新韌體有執行，但沒有自己 confirm下次重開機會自動退回舊版；檢查新韌體是否正常
244-byte writes rejected（Traffic log）瀏覽器不接受大封包，已自動改用 20 bytes不需處理，只是速度變慢

上傳卡住沒有反應時，按 Disconnect 後重新 Connect，再按 Update 即可繼續。

9注意事項

  • 馬達安全：板子只在「開始上傳」與「重開機」時檢查馬達狀態。上傳中途收到 CAN 換檔命令會照常執行，上傳也繼續；重開機前韌體會先停止馬達。
  • 版本號：每次發布都要改 VERSION。韌體不阻擋降版，頁面只會先詢問。
  • 自動退版：新映像以 test 模式開機，韌體在藍牙正常、看門狗持續餵食約 5 秒後才自己 confirm。在這之前當機或重開機，MCUboot 會退回舊版。
  • 設定保留：更新不會清除已教的零點（Z）與藍牙綁定資料，它們存在獨立的 storage 區。
  • 安全性：SMP 沒有配對保護，範圍內任何人都能上傳或重開機。簽章只能擋住外來映像開機，擋不住惡意重開機。
  • 簽章金鑰：mcuboot_priv.pem 放在專案外、不可 commit，且必須備份。金鑰遺失後，已出貨的板子將無法再用藍牙更新。
  • 單一連線：更新時不能同時用手機 App 連線。
